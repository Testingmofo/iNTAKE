# iNTAKE

iNTAKE is a Windows media-download manager built with JavaFX and yt-dlp. It provides a Cyberpunk-inspired desktop interface, background downloads through the system tray, download history, configurable audio and video formats, playlist controls, and a companion browser extension.

This repository contains the current JavaFX edition. The original PowerShell edition remains available from the repository's earlier history and is referred to as **iNTAKE-Powershell**.

## Features

- Queue-based, asynchronous yt-dlp downloads
- Audio and video format selection
- Separate audio and video output locations
- MVSS local music-vibe analysis and automatic audio-library sorting
- Persistent Main/Accent/Highlight color customization with cyberpunk presets
- Playlist ignore and selection controls
- Download progress, history, logs, and error reports
- System-tray operation and silent browser-extension startup
- Chrome and Edge browser extension with native messaging
- SHA-256-verified application and managed-extension updates
- Self-contained Windows installer and portable package generation

## Running from source

Development requires Windows, JDK 17 or newer, Maven, yt-dlp, FFmpeg/FFprobe, and Deno available on `PATH`.

```powershell
mvn clean javafx:run
```

Alternatively, run `Launch iNTAKE.cmd`. The launcher checks the required tools and can use Chocolatey to install or update missing dependencies.

See [LAUNCHING.md](LAUNCHING.md) for launcher details.

## Building a Windows release

The release builder requires Chocolatey, WiX Toolset 3.x, JDK tooling, Maven, yt-dlp, FFmpeg, and Deno.

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File scripts\Build-Release.ps1
```

Generated installers and archives are placed in `For-Release`. That directory is intentionally excluded from Git because release binaries should be uploaded as GitHub Release assets.

## Browser extension

The unpacked extension is located in `browser-extension`. Release builds also produce a ZIP archive that can be attached to a GitHub Release.

The extension communicates with the local iNTAKE application. If iNTAKE is offline, its native-messaging helper starts the application silently before forwarding the download request.

Installed releases copy the current extension into `%LOCALAPPDATA%\iNTAKE\browser-extension`. Load that managed directory once from `chrome://extensions` or `edge://extensions` using **Load unpacked**. Future iNTAKE application updates replace the managed files, and extension version 1.3.3 or newer checks them every 30 minutes and reloads itself when its on-disk version changes. Existing installations loaded from the source tree or an extracted ZIP require this one-time migration because Chrome and Edge do not permit ordinary self-hosted extensions to silently change their installation source.

## Automatic beta updates

On a normal packaged launch, iNTAKE checks the repository's published GitHub Releases for a newer `vX.Y.Z-beta` tag. Silent browser wake-ups do not interrupt the user with an update prompt. If an update is accepted, iNTAKE:

1. Downloads the matching `iNTAKE-Setup-X.Y.Z-beta.exe` and `SHA256SUMS.txt` release assets.
2. Verifies the installer with SHA-256 before changing the current installation.
3. Starts a detached updater, exits all running iNTAKE instances, and removes the registered MSI installation.
4. Runs the verified setup silently with the previous installation directory and relaunches iNTAKE.

If verification or download fails, the installed version is left unchanged. Transaction details are written beside the staged installer under `%LOCALAPPDATA%\iNTAKE\updates`. The updater depends on the release asset names generated by `scripts\Build-Release.ps1`; renaming those GitHub assets disables automatic installation for that release.

## YouTube access challenges

YouTube may temporarily rate-limit an IP address or require a signed-in browser session. In the configuration matrix, **YouTube Session // Cookies from Browser** can be set to Firefox, Chrome, Edge, Brave, Vivaldi, Opera, or Opera GX. The setting is off by default and is applied only to YouTube requests. iNTAKE stores only the selected browser name; yt-dlp reads the browser session at execution time. Opera GX is routed through its Windows profile path because yt-dlp's ordinary `opera` lookup targets Opera Stable. Selecting Opera GX displays a warning and authorizes iNTAKE to close the browser, end remaining background processes after a graceful timeout, and reopen the previous session once yt-dlp starts transferring media. Save forms and other browser work before using this mode. If another Chromium-based browser reports a locked or inaccessible cookie database, close all of that browser's windows and background processes before retrying.

Before enabling it, open the affected video in that browser and complete any CAPTCHA or sign-in challenge. Account-backed downloading can result in temporary or permanent YouTube account restrictions, so use it only when necessary and never share exported cookies or session data. iNTAKE also applies a one-second delay between YouTube metadata requests to reduce avoidable request bursts.

## MVSS automatic audio sorting

Enable **Auto Sort via MVSS** in the main control bar to analyze completed audio downloads locally. MVSS decodes a short sample through FFmpeg, measures tempo, energy, brightness, zero-crossing activity, and dynamics, then moves the file into:

```text
<Audio download location>\MVSS\<Vibe>\
```

The configuration matrix contains an **MVSS Audio Themes // Topics** editor. Define one destination topic per line using:

```text
Topic name | keyword, keyword, mood hint
```

For example, `Boss Music | boss, battle, intense, game` creates an `MVSS\Boss Music` folder and gives the offline classifier matching hints. Topic names and hints persist in `intake.properties`. The default topics remain `Energetic`, `Chill`, `Dark`, `Bright`, `Melancholic`, and `Atmospheric`, and existing files are never overwritten; MVSS adds a numeric suffix when necessary.

The acoustic classifier works fully offline by combining measured audio features with configured topic hints. If Ollama is already running with a small local model (up to roughly 3B parameters), MVSS asks it to choose only from the configured topic list as an optional refinement step. Ollama is not required.

## Cyberpunk theme customization

Open the configuration matrix from the top-right settings control to customize the three interface roles:

- **Main** — primary buttons, major borders, and success states
- **Accent** — telemetry, secondary borders, icons, and online states
- **Highlight** — warnings, errors, paused states, and alert hovers

Built-in presets include Neon District, Netrunner Ice, Arasaka Alert, Toxic Chrome, and Synthwave Grid. Custom colors apply immediately after saving and persist in `intake.properties`. **Reset Neon District** restores the original yellow, cyan, and magenta palette.
